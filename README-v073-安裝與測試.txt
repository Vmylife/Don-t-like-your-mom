DON'T LIKE YOUR MOM v0.7.3｜投稿壓縮＋漸進預載＋舊照片壓縮

A. GitHub (只改檔，不動舊照片及 leaderboard-config.js)
覆蓋：index.html、script.js、sw.js、photo-preload.js、submit.html、admin.html、community-ui.js、community-api.js。
新增：photo-compress.js（非常重要，投稿頁和管理員頁共用）。
請確認新增檔案 photo-compress.js 與其他程式同一個根目錄。

B. Supabase (只為管理員「壓縮舊照片」功能需要)
開啟原本的 Supabase Project → SQL Editor → New query。
貼入 setup-photo-optimization-v073.sql 完整內容 → Run。
如果你只要新投稿壓縮和分批預載，不執行這份 SQL 也能用；
但管理員「壓縮舊照片」按鈕會因無更新權限而無法覆蓋。
此 SQL 不刪除、搬動、更改既有照片，不影響排行榜、日冠或雙人房間。
不必重新執行舊的 v0.7.0 / v0.7.2 SQL。

C. 新照片
投稿圖片最長邊 1200 像素，目標約 300 KB，保證輸出的檔案最多 500 KB。
優先 WebP，不支援時改用 JPEG；重新繪製後不保留 EXIF。
原圖仍限制 8 MB；只是壓縮目標更小，不會更動其他玩家已投稿內容。

D. 遊戲圖片快取
每局開始先下載 18 張照片（原本要等 60 張）：自由模式前 5 張「實際題目」會保證載入，
其餘 13 張為候選圖片；剩餘照片在遊戲開始後低併發下載。
挑戰／房間固定題目可精確先下載前 18 張；自由模式因抽卡機率隨 LIKE 改變，
前 5 張固定預載，其餘圖片只是可能用到的候選，不能保證全部剛好是首 18 張。
滑到未解碼完成的照片時，仍會顯示「照片載入中」，不能盲滑。
首次載入時間通常應較短，但仍取決於網路速度與裝置。

E. 舊的已核准照片（選用）
admin.html 管理員登入 → 已公開 → 該照片旁的「🗜️ 壓縮舊照片」。
按鈕只優化你手動選擇的照片，且保持原 URL、格式、副檔名與既有 DB 記錄不變。
圖片已 <=500 KB 時自動略過。不支援 WebP 編碼的 iPhone 請用電腦 Chrome 處理 .webp。
覆蓋 Storage 完成後，原圖片可能仍在 CDN／瀏覽器快取一段時間；稍後重新整理即可。
請先用一張舊照片測試，再批次進行。無任何自動全庫覆寫或刪除。

F. 測試
1. 網站首頁應顯示 v0.7.3；進自由模式，按開始後看首批 18 張的進度。
2. 用 iPhone Safari 投稿照片，觀察壓縮完成訊息，最後應出現投稿成功。
3. 用管理員審核頁確認新照片在私人待審區，批准後在自由模式抽牌。
4. 若想壓縮舊照，先執行 SQL 再挑一張已公開照片按壓縮。
5. 請 Android 玩家重新載入 v0.7.3，檢查預載速度和空白照片。

程式語法與模擬圖片壓縮已本地測試；真正 Supabase 上傳、替換舊圖，以及 Android 實機仍需部署後驗證。
